## Default v4.2 Support Contract

The default v4.2 scope is **certified `embedded-core-v1` only**.

The release may describe the pure embedded Datalog closure as structurally certified only if `scripts/verify_embedded_core_v1.sh` passes on the immutable candidate SHA. That closure is explicitly limited to local domain data and deterministic algorithms.

The following remain **experimental or otherwise excluded from the v4.2 certification claim** unless fresh, candidate-SHA evidence separately proves them:

- sharding and distributed query orchestration;
- Raft/HA, replication, remote failover, quorum and coordinated writes;
- storage/FFI and transport adapters;
- MCP and network-facing surfaces;
- long-soak, upgrade/rollback, destructive-storage, independent-host, LAN/WAN fault, and lifecycle-promotion claims.

This is a support boundary, not a claim that those modules do not exist. They can be present in the candidate while remaining explicitly experimental.

## Candidate Inclusion Rationale

This candidate preserves all source, tests, documentation, and scripts listed above because each contributes to either the certified embedded-core boundary or to a deliberately fail-closed experimental-surface boundary. Nothing under `build/`, `Mnesia.nonode@nohost/`, or `artifacts/` is eligible for staging.

| Ownership boundary | Candidate content | Compatibility and evidence |
|---|---|---|
| Embedded data and deterministic algorithms | fact/query/command/Raft model, vector validation and exact oracle | `embedded-core-v1` profile, vector and HNSW tests, boundary fixtures. |
| Transaction domain and runtime interpreter | `transactor/domain`, `transactor/runtime`, public API wrappers | Characterization tests keep explicit errors/deadlines primary and retain compatibility wrappers intentionally. |
| State ownership and continuation policy | `shared/ownership`, `continuation` | Ownership projection and idempotent continuation regressions; no actor/storage/transport imports in pure policy. |
| Sharding and durability | sharding semantics, sharded runtime, Raft durability FFI/harness | Included only as experimental: broader-stability gate controls any future promotion claim. |
| Certification and release evidence | profile, boundary checker, CI job, reports | Verifier rejects generated/runtime paths, unapproved pure imports, forbidden runtime imports, and malformed/exclusion-free metadata. |

## Existing Automation

### CI: `.github/workflows/ci.yml`

The repository has CI for pull requests and pushes to `master`/`main`. It runs formatting, docs, the full Gleam test suite, `embedded-core-v1` boundary verification, distributed safety, evidence harnesses, Mnesia-isolated tests, and `actionlint`.

The new `embedded-core-boundaries` job is present only in the current dirty worktree and therefore is not yet candidate evidence.

### Release: `.github/workflows/release.yml`

A tag matching `v*` triggers docs, tests, a tag-to-`gleam.toml` version parity check, GitHub Release creation, and conditional Hex publication. A manual run supports `skip_publish`.

Release metadata currently has a single source for package version (`gleam.toml`) but the README, changelog, and tag must still be synchronized manually. v4.2 work will add a mechanical check for that broader consistency.
